# Календарь звонков

[![hexlet-check](https://github.com/noname093pxg1gq678/ai-for-developers-project-386/actions/workflows/hexlet-check.yml/badge.svg)](https://github.com/noname093pxg1gq678/ai-for-developers-project-386/actions)

Сервис записи на звонок по мотивам Cal.com. Владелец календаря публикует доступное время, а гость выбирает свободный слот и записывается на встречу - без регистрации, личных кабинетов и внешних календарей.

Учебный проект Хекслета: https://ru.hexlet.io/programs/ai-for-developers
Как это должно работать: https://files.hexlet.app/a/2ipc5m

## Сценарий использования

Сценарий проверен на референсе: в Cal.com создан тип встречи «Звонок на 45 минут» с описанием и длительностью, с публичной страницы владельца забронирован свободный слот, бронирование появилось в списке предстоящих встреч владельца и закрыло слот для повторного выбора.

### Владелец

1. Заходит в приложение - владелец один, задан заранее, авторизации нет.
2. Создаёт тип встречи: название («Звонок на 45 минут»), описание («Созвон для обсуждения проекта. Подготовьте вопросы заранее.»), длительность (45 минут).
3. Тип встречи сразу появляется на публичной странице владельца.
4. Открывает список предстоящих встреч всех типов: название встречи, имя гостя, его комментарий, дата и время.

### Гость

1. Без регистрации открывает публичную страницу владельца и видит типы встреч: название, описание, длительность.
2. Выбирает тип - открывается календарь на окно записи: 14 календарных дней, окно сдвигается с течением времени.
3. Выбирает день и видит свободные слоты. Слот длится столько, сколько выбранный тип встречи; шаг доступных стартов зафиксирован в спецификации.
4. Выбирает слот (например, ср 18 ноября, 09:00-09:45), заполняет имя, email и комментарий, подтверждает.
5. Получает экран успеха с деталями встречи.

### Замыкание цикла

Бронирование сразу появляется в списке владельца, а занятый слот исчезает из доступных. Соседний слот, начинающийся в момент окончания встречи, остаётся доступным: пересечения запрещены, но встречи «вплотную» разрешены. Одно и то же время нельзя занять дважды, даже разными типами встреч, в том числе при двух запросах, пришедших одновременно.

## Обязательные функции

- Типы встреч: создание, редактирование, удаление, список (название, описание, длительность)
- Публичная страница владельца со списком типов встреч
- Календарь доступности на 14 календарных дней
- Список свободных слотов с учётом уже занятого времени
- Бронирование слота гостем без регистрации: имя, email, комментарий
- Список предстоящих встреч владельца по всем типам
- Атомарность бронирования: при одновременных запросах на один слот успех получает только один

## Ограничения

- Нет авторизации, личных кабинетов, email-уведомлений и интеграций с внешними календарями
- Владелец календаря один и задан заранее
- Пересечение интервалов запрещено, включая частичное наложение разных типов встреч; следующая встреча может начинаться в момент окончания предыдущей
- Часы работы владельца, часовой пояс, начало окна записи (сегодня или завтра) и шаг стартов слотов фиксируются в спецификации API
- Данные хранятся в памяти процесса: перезапуск приложения сбрасывает записи
- Приложение собирается в Docker-образ и запускается в контейнере

## Контракт API и генерация клиента

Работа с API строится вокруг контракта:

1. **TypeSpec-контракт** - источник истины для API.
2. **OpenAPI-спецификация** - генерируется из TypeSpec автоматически.
3. **Клиентский SDK** - генерируется из OpenAPI для фронтенда (`@hey-api/openapi-ts`).

Fastify не генерирует серверные маршруты из OpenAPI, поэтому бекенд реализуется вручную по контракту и проверяется тестами на соответствие спецификации.

## Стек

- **Контракт:** TypeSpec → OpenAPI 3.0
- **Бекенд:** Node.js + TypeScript + Fastify; данные в памяти процесса
- **Фронтенд:** React (Vite) + TypeScript + Mantine; API-клиент генерируется из OpenAPI
- **Тесты:** Vitest
- **Инструменты:** mise (версии и задачи), hk (git-хуки), oxlint + oxfmt (линт и форматирование)
- **Сборка и запуск:** Docker

## Установка

Требуется [mise](https://mise.jdx.dev/). Команды проекта описаны в [AGENTS.md](AGENTS.md).

```bash
git clone https://github.com/noname093pxg1gq678/ai-for-developers-project-386.git
cd ai-for-developers-project-386
mise run setup   # инструменты, npm-зависимости, git-хуки
mise run dev     # бекенд http://localhost:3000, фронтенд http://localhost:5173
```

Все проверки: `mise run check` - ту же команду запускает CI на каждый push.

## Использование

Локально: приложение - http://localhost:5173, бекенд (только API) - http://localhost:3000:

```bash
mise run setup
mise run dev
```

В контейнере - один образ: бекенд раздаёт собранный фронтенд и API на одном порту :3000:

```bash
docker build -t call-booking .
docker run --rm -p 3000:3000 call-booking
```

Откройте http://localhost:3000 - публичная страница для гостей. Панель владельца доступна только по прямому URL http://localhost:3000/admin - переходов между поверхностями нет (см. [ADR 0001](docs/adr/0001-disconnected-surfaces.md)). Здоровье API - http://localhost:3000/api/health, по нему же контейнер делает HEALTHCHECK.
